# Supermole.app (`app/`)

A one-window SwiftUI front end, in English and French, for people who never open Terminal. It ships in `Installer-Supermole.dmg`; installing `mo` and the dmg itself are covered in `.claude/rules/install-update.md`.

- **The app drives the installed `mo`; it never re-implements it.** Every scan, list and deletion is a `mo` command run by `MoleRunner` (`app/Sources/SupermoleCore/MoleRunner.swift`), so the safety rules of the CLI (protected paths, Trash by default, operation logs) apply unchanged. A section needs a machine-readable mode? Add it to `mo` with its own Bats tests, then read it from the app.
  - Runs get `NO_COLOR=1`, `TERM=dumb`, a PATH that also holds `~/.local/bin` and Homebrew (a GUI app inherits neither), stdin from `/dev/null`, and never `MOLE_DELETE_MODE`. `mo` refuses root, so the app never elevates a whole `mo` run.
  - Nothing is deleted without a preview first and an explicit click on a button naming the action.
- **Read-only sections use the JSON `mo` already has:** `status --watch --interval 2s` (one object per line; stopping the stream terminates `mo`), `analyze --json [path]` (flag before path; a partial scan exits 0, so read `scan_status`), `history --json --limit N`, and the explain answers `mo analyze` saves in `~/.cache/mole/explain/answers.json`.
- **Kept results.** Analyze, the Apps list and History show at once the JSON `mo` printed last time (`ResultCache`, one file per command under `~/Library/Caches/<bundle id>/results`, at most 200, written by `MoleRunner.decode(_:_:keepingIn:)`), then read a fresh one unless the kept one is recent: `DiskModel.overviewFreshness` (15 min), `DiskModel.folderFreshness` and `UninstallModel.listFreshness` (5 min); History always reads again, and Refresh or R always measures. `UpdatedLabel` says how old a kept result on screen is. A preview a deletion acts on (Clean up, Slim down, the uninstall plan) is never kept: it is always read fresh.
- **Clean up** previews with `mo clean --dry-run --json` (`CleanPreview`, read with `MoleRunner.decodeReport`, which accepts the JSON an early stop still prints) and cleans with plain `mo clean` after its own confirmation, which names the Trash when the preview empties it. Without a terminal `mo clean` starts at once and skips the system section unless an administrator session exists. Progress comes from the `➤ Name` section headers (`CleanProgress`), for display only; the result is read back from `mo history --json --limit 1`. Agents never press Clean up on a real Mac: preview only, the person cleans.
- **Analyze is driven like `mo analyze`:** a selection moved with ↑↓, → or Return to open, ← Esc or Delete to go back, E to explain the selected row (again for the read-only deep look when the answer asks for it), ⇧E for every row on screen, O, P (Quick Look), F and R as in the terminal. The explain panel under the list mirrors the terminal's (`cmd/analyze/explain_view.go`): the title with size and provider, the `● VERDICT · source · réponse du jj/mm` line, then « C'est quoi », « Si je supprime », « Conseil », with the terminal's French words. Requests go through `mo analyze --explain` one at a time (`ExplainRequest`, batches of the terminal's size).
- **Apps has two tabs, each a preview then a run after an alert naming the Trash.** Uninstall lists `mo uninstall --list` (`InstalledApp`; when a newly seen app has no size yet, one more listing after `UninstallModel.sizeRefreshDelay` fills it in), previews the ticked apps by bundle path with `mo uninstall --dry-run --json` (`UninstallPlan`), sets aside the apps that need an administrator and previews the rest again on their own so the plan shown is exactly what runs, then runs `UninstallPlan.uninstallArguments()`, `mo uninstall --yes --plan=<plan_digest> [--with-data] <paths>`, so `mo` refuses anything but that plan; when it exits 65 (the apps changed since the preview, nothing removed) the app previews again with a notice. The "my data" switch previews again with `--with-data`. The result is `mo history --json --limit 1` plus a disk check of each planned path. Slim down scans with `mo slim --dry-run --json` (`SlimPreview`), ticks nothing, and runs `mo slim --yes <paths>`. Both lists share `SelectableAppRow` and `Binding<Set<String>>.contains`; the run screens share `WorkingCard`, `RunResultCard`, `LogCard` and `PathLine` (`ActionCards.swift`) with Clean up, and every run keeps its tail in `RunLog`. Agents never press Uninstall apps or Slim apps on a real Mac except on an app they created for the test (`~/Applications/SupermoleSelfTest.app`, plain bundle id `com.supermole.selftest`).
- **The engine is never older than the app.** The dmg build stamps the app with `mo`'s VERSION, and `MoleLocator.choose` drives the first `mo` at least that new (`EngineVersion`, read from `mo --version`): a Terminal install left on an older release lacks commands the app runs (`analyze --explain` failed with `flag provided but not defined`). When every `mo` found is older, `AppModel` installs a copy for the account in `~/.local/bin` on its own (`.updatingEngine`), never touching the one in `/usr/local/bin`; still older after that, it stops with a message and Try again. `-MolePath` is taken whatever its version, and a build with no bundle version checks nothing.
- **Full Disk Access.** `mo` runs as the app's child, so macOS applies the app's access to it. `FullDiskAccess.status()` (SupermoleCore) reads protected places the way `has_full_disk_access` in `lib/core/ui.sh` does, the system TCC database first since every Mac has one; a read never makes macOS ask. When the access is denied once `mo` is found, `SetupView` shows `FullDiskAccessStep`: its button opens System Settings at Full Disk Access (`FullDiskAccess.settingsURL`), and the app checks again each time it comes back to the front. "Continue without" is remembered (`AppModel.fullDiskAccessDeclinedKey`) and forgotten once the access is seen granted, so losing it again (each update of the ad hoc signed app changes its code hash) brings the step back. The Settings window shows the state with the same button, and Clean up says when part of the Mac went unseen. Agents never grant the access, which takes the person's password or Touch ID.
- **Trying the app against a checkout:** `open Supermole.app --args -MolePath /path/to/checkout/mole` (`MoleLocator.overrideKey`) drives that `mo` before any installed one, so a new CLI mode can be exercised before it ships.
- **macOS 26 is the app's floor**, for Liquid Glass (`glassEffect`, `GlassEffectContainer`, `.glass` / `.glassProminent` buttons); `mo` itself stays on macOS 12. Owner decision 2026-10-30: no fallback look for older systems. The build checks each slice against 26.0 (`INSTALLER_MIN_MACOS` in `scripts/build_installer_dmg.sh`).
- **Design.** Four spaces in the sidebar (Home, Clean up, Apps, Disk space); History is the inspector and Settings the standard Settings window. Cards are `GlassCard` over `AmbientBackground` (a brand-colored `MeshGradient` the glass refracts); charts are Swift Charts or the shared `RingGauge` / `Sparkline` / `StorageDonut`. A layout that switches on width measures a container its choice cannot resize (the scroll view): measuring the content it rearranges looped AppKit's constraint pass and aborted the app. Keep redraws cheap: work a result out once when it arrives (`DiskModel.entries` sorted with a path index, `CleanPreview.Layout`, `UninstallModel.shownApps` rearranged only when the listing, search or order changes), never in `body`; long lists sit in a `LazyVStack` inside a `GlassCard(liftsOnHover: false)`; app icons come from `AppIconStore`, drawn off the main thread once per app and size; a space's entrance cascade plays on its first visit only (`playsEntrance`, set by `RootView`), and a cascade stops after a few cards.
- **Localization.** The Swift sources are written in English and their text is the key. `app/Resources/fr.lproj/Localizable.strings` translates every key; `scripts/check_app_localization.py` compares it with the list the compiler emits (`-emit-localized-strings`) and fails the dmg build on a missing or stale key. Words that come from `mo` itself (overview places, health ratings and issues, battery condition) go through `MoleTerms` and the `MoleTerms.strings` tables, keyed `<context>.<term>`, and fall back to `mo`'s English. Show them with `Text(verbatim:)`: a folder name with `%` must not be read as a format.
- **Tests.** `SupermoleCore` holds everything that is not a view and is covered by `swift test` (run by step 3 of `scripts/test.sh`). Fixtures are written by hand: never commit real `mo` output, which carries the machine name and the user's file names.
